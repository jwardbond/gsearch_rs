Path scoring options

Setup: T is a rigid transform that moves Q onto G. φ maps each node of Q to a node of G. For each edge (u,v) of Q, we find the best path P in G from φ(u) to φ(v). We need a score that is low for a good match. The lowest score over all φ and T is the answer.

The four options

In all options, T is fitted with Procrustes (Frobenius error on the nodes). The options differ in how they score the path P for each edge (u,v) of Q. Let L = ‖T(u) − T(v)‖ be the length of the moved Q edge.

The last column. Each option has its own dist function, so it has its own S. The last column asks: does the algorithm find the φ and T that minimize that S? It checks the three steps of the algorithm (see "Does the algorithm minimize S?" below): the best path, the φ filter, and the fit of T.

What this means

  • Only Fréchet has the end-point property. The other options do not check that the path covers the Q edge.
  • Without the end-point property, the φ filter and the Procrustes fit have no guarantee. The path step is still exact for options 2 and 3.
  • Options 2 and 3 are sums. Dijkstra is exact for them. They are the cheap choice.
  • Option 2 is better than option 3. It stops most overshoot. It does not stop undershoot.
  • Option 4 does not use the Q edge shape. Use it only inside a corridor, if at all.
  • You can add the end-point terms ‖T(u) − φ(u)‖ + ‖T(v) − φ(v)‖ to option 2. This gives it the end-point property. Dijkstra stays exact, because the terms do not depend on P.
  • Divide an area by the Q edge length to get a mean distance.
  • Nodes of Q with no edges get no cost in all four options.

Does the algorithm minimize S?

The formulation is: find φ and T that minimize S. The algorithm has three steps. Only the first step is exact. Each step is shown below.

Step 1: best path P for a fixed φ and T. Exact.

  • Dijkstra finds the true minimum when the path cost is a sum of non-negative terms.
  • The area costs are such sums. The shortest-path cost is a sum only when the shortest path is at least L (see the table).
  • Put the ε-corridor in the definition of the path set. Then the minimum is exact.
  • Fréchet and Hausdorff are not sums. Dijkstra is not exact for them. The path step for D needs a map-matching algorithm.

Step 2: best φ. Exact only for the kept candidates.

  • The annulus and triangulation filters remove some φ.
  • You must show that they never remove a φ with a low score.
  • The proof needs this property of dist: dist is at least the offset of each end point. That is: dist(T(u,v), P) ≥ max(‖T(u) − φ(u)‖, ‖T(v) − φ(v)‖).
  • Fréchet has this property. The two area options and the shortest-path option do not. See the "where it fails" figures.
  • Assume a match has S ≤ δ. Then each node is at most δ from its target.
  • T is an isometry. So each annulus distance changes by at most 2δ.
  • Therefore tol = 2δ removes no match with S ≤ δ.

Step 3: best T. Not exact. The proof gives a bound.

  • Procrustes minimizes the node error. It does not minimize S.
  • Let T* be the best T for S. Let T' be the Procrustes T. Let S* be the best score.
  • Use the end-point property. Then the sum of squared node offsets under T* is at most 2·S*².
  • Procrustes does not do worse than T* on this sum. So its sum is also at most 2·S*².
  • Therefore no node moves more than √8 · S* between T* and T'.
  • A rigid map moves a segment by at most the larger end-point move. So S(T') ≤ (1 + c·|EQ|) · S*, where c is a constant.
  • The bound is weak, but it gives two useful results.
    • If S* = 0, then T' is optimal. A perfect overlap is always found.
    • If S* is small, then T' is close to optimal.
  • To get closer to the minimum, refit T on the path points after Dijkstra. This can only decrease S.

Note: these steps have not been checked in detail. Check the constants before you use them in the paper.

The problem with the Python distance

Steps 2 and 3 need the end-point property. The Python code uses distance to a segment. It does not have this property. There are two options.

  1. Define dist as Fréchet. The proofs hold. Dijkstra is not exact.
  2. Define dist as the segment-area cost plus ‖T(u) − φ(u)‖ + ‖T(v) − φ(v)‖. The proofs hold. The end-point terms do not depend on P, so Dijkstra stays exact. Each node is counted once for each edge that touches it.

Option 2 is the better choice.

Suggestion

  1. Fit T with Procrustes. This is cheap.
  2. For the proofs, use Fréchet, or use option 2 (area to segment) with the end-point terms.
  3. Do not use option 3 or option 4 alone.
